# Contributing to Purgearr

## Local dev setup

```bash
git clone https://gitlab.com/grumpypillow/purgearr
cd purgearr
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Create a local `.env` file (never commit this):

```bash
DATABASE_URL=sqlite:///./data/purgearr.db
SECRET_KEY=dev-key-change-me
```

Run the dev server:

```bash
DATABASE_URL=sqlite:///./data/purgearr.db SECRET_KEY=dev-key uvicorn app.main:app --reload --port 8765
```

Navigate to `http://localhost:8765` — first run prompts account creation.

## Project structure

```
app/
  connectors/     # External API clients (Plex, Jellyfin, Sonarr, Radarr, qBittorrent, …)
  routes/         # FastAPI route handlers
  services/       # Business logic (rules_engine.py, sync.py)
  models/         # SQLAlchemy ORM models
  templates/      # Jinja2 HTML templates
    partials/     # Fragments swapped by HTMX (rules list, library grid, …)
  static/         # app.js, PWA manifest, icons
  auth/           # JWT middleware and login logic
  main.py         # App entry point, route registration, APScheduler setup
```

## Before committing

1. **No secrets** — run `grep -rE "password|secret|api_key|token" --include="*.py" app/` and make sure no hardcoded values slipped in
2. **Syntax check** — `find app scripts -name "*.py" | xargs python3 -m py_compile`
3. **app.js cache-buster** — if you modify `app/static/app.js`, increment the `?v=N` query string in `app/templates/base.html`
4. **Jinja2 + onclick** — never use `| tojson` inside an HTML `onclick="..."` attribute (the double quotes break the attribute). Use `'{{ value | replace("'", "\\'") }}'` instead.
5. **Conventional commits** — write `type: description` (`feat`/`fix`/`docs`/`refactor`/`perf`/`ci`/`chore`/`build`/`test`); the CHANGELOG is generated from these messages
6. **Tests** — run `python3 -m pytest` (suite lives in `tests/`)
7. **DB migrations** — if you add or change a model column, also add it to `migrate_db()` in `app/database.py` (idempotent `ALTER TABLE`); `create_all()` only creates missing tables, it won't alter existing databases

## Adding a new connector

1. Create `app/connectors/my_service.py` with a class following the pattern of existing connectors (constructor takes URL + token/key, methods return plain dicts)
2. Add the relevant settings keys to `app/routes/settings.py` and the Settings UI
3. Wire it into `app/services/sync.py` if it provides library/watch data, or into `app/services/rules_engine.py` if it's an action target
4. Add connection test support in the settings test endpoint

## CI pipeline

Push to `main` → lint (py_compile + import check) → Docker build → push `registry.gitlab.com/grumpypillow/purgearr:latest`

Tag `vX.Y.Z` → same as above + also pushes the `vX.Y.Z` and `X.Y` image tags + creates a GitLab Release (notes generated by git-cliff)

## Releasing

1. `git cliff --unreleased --tag vX.Y.Z --prepend CHANGELOG.md` — adds the new section on top, preserving the manual pre-0.5.0 history
2. `git add CHANGELOG.md && git commit -m "chore(release): vX.Y.Z"`
3. `git tag vX.Y.Z && git push origin main vX.Y.Z`

> Do **not** run `git cliff --output CHANGELOG.md` — a full regeneration would drop the pre-v0.5.0 sections, which have no git tags.
